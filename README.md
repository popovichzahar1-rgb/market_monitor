# Market Monitor

Особистий конвеєр моніторингу подій, що впливають на ринки акцій і крипти,
зі сповіщеннями в Telegram. **Лише збір і фільтрація інформації, жодної
автоматичної торгівлі. Не є фінансовою порадою.**

> Статус: етап 6 з 7 (GitHub Actions і збереження стану).
> Повна інструкція (BotFather, GitHub Secrets, Actions) з'явиться на етапі 7.

## Швидкий старт локально

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env            # секрети поки не потрібні
python -m pytest                # тести на фікстурах, без мережі
python -m market_monitor run --dry-run   # реальні RSS, друк замість відправки
python -m market_monitor status          # стан джерел
```

Повторний `run --dry-run` покаже «Нових записів немає»: дедуплікація за URL
працює, а незмінені фіди віддають `304 Not Modified`.

## Конфігурація

- `config.yaml` — робочий конфіг (без секретів), список відстеження порожній.
- `config.example.yaml` — те саме з **прикладами** компаній (не рекомендації).
- `.env` / GitHub Secrets — токени й ключі (див. `.env.example`).

## Джерела

| Модуль | Що дає | Ключ | Ліміти / умови |
|---|---|---|---|
| `rss` | ФРС, ЄЦБ, Банк Англії, Банк Японії, прес-релізи SEC, CNBC, MarketWatch, BBC, Al Jazeera, OilPrice, EIA, Kyiv Independent, SCMP, CoinDesk, Cointelegraph, Decrypt | — | умовні запити (ETag), robots.txt, ≥1 с між запитами до хоста |
| `gdelt` | світовий пошук новин: енергетика/санкції, центробанки, крипто-події, аварії, Східна Європа, Китай | — | 1 запит / 5 с → кожен запит ≈ +5,5 с до запуску |
| `sec_edgar` | 8-K, 10-Q, 10-K, 6-K, 20-F компаній зі списку | `SEC_CONTACT_EMAIL` | ≤10 запитів/с, User-Agent з контактом (вимога SEC) |
| `fred` | CPI, PCE, payrolls, безробіття, HICP єврозони; різкі рухи ставки ФРС, 10Y, VIX, Brent, газу; календар релізів на 7 днів | `FRED_API_KEY` | 120 запитів/хв |
| `coingecko` | BTC/ETH ±7 % за 24 год, ринок крипти ±5 % | — | публічний безключовий тариф, 2 запити за запуск |
| `usgs` | землетруси M≥6.5 або PAGER orange/red | — | публічний фід |

Пороги й списки змінюються в `config.yaml`. Збій джерела видно в
`python -m market_monitor status` і в рядку «Джерела» повідомлення.

## Дедуплікація

1. Нормалізований URL (без utm/fbclid/www) і раніше бачені URL дублікатів.
2. Хеш тексту (передруки однієї статті).
3. Схожі заголовки (rapidfuzz ≥ 90) за 48 год, але лише якщо збігаються числа,
   абревіатури й власні назви: «Fed holds rates» і «ECB holds rates» лишаються окремими.

Дублікат не зберігається окремо, а збільшує лічильник `mentions` оригіналу:
що більше джерел пише про подію, то вагоміша вона для скорингу (етап 3).

## Оцінка важливості (0–100)

`оцінка = правила + величина даних + бонуси + тон тексту`

- **Правила** (`scoring.rules` у config.yaml): ключові слова з вагами. Якщо
  спрацювало кілька правил, кожне наступне додає вдвічі менше (50 → 25 → 12).
  Правила з `alert: true` позначають термінові категорії (рішення центробанків,
  хак біржі, рішення щодо ETF, регуляція крипти, санкції, удари по енергетиці, OPEC+).
  Шумові правила (opinion, podcast, «best stocks to buy») мають від'ємну вагу.
- **Дані**: рух ціни (чим більший, тим вище), великі релізи (CPI, PCE, payrolls),
  магнітуда й рівень PAGER землетрусу, 8-K з важливими пунктами.
- **Бонуси**: вага джерела (офіційні ФРС/ЄЦБ вище, GDELT нижче), кількість
  джерел, що пишуть про подію, згадка BTC/ETH, твої регіони, компанія зі списку.
- **Тон** (FinBERT): до +10 за виразний тон і ще +5 за явно негативний.
  Модель запускається лише для записів, що вже набрали ≥ `prefilter_min` (25).

Ключові слова: написані малими літерами збігаються з будь-яким регістром;
з великою літерою (Fed, SEC, ETF, US) враховують регістр; `*` означає будь-яке
закінчення (`sanction*`).

Перевірити, як оцінюється заголовок:

```bash
python -m market_monitor explain "OPEC+ agrees surprise output cut" --source rss:oilprice
```

## Telegram

### Підключення бота (2 хв)

1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте ім'я → отримайте токен
   вигляду `123456789:AA...`. Це `TELEGRAM_BOT_TOKEN`; нікому його не показуйте.
2. Напишіть своєму боту будь-що (наприклад, `/start`).
3. Відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` у браузері й знайдіть
   `"chat":{"id":123456789` — це `TELEGRAM_CHAT_ID`. Лише цей чат зможе керувати ботом.
4. Впишіть обидва значення в `.env` (локально) або в GitHub Secrets (етап 6).

```bash
python -m market_monitor run --dry-run      # друкує, нічого не надсилає й не «з'їдає» команди
python -m market_monitor run                # справжня відправка
python -m market_monitor digest --force     # дайджест просто зараз
```

### Алерти за замовчуванням (усе в `alerts:` у config.yaml)

| Що | Поріг | Чому так |
|---|---|---|
| Рішення центробанку (ФРС, ЄЦБ, BoE, BoJ, НБК…) | завжди від 55 | ставки рухають усі ринки; 55 відсікає здогадки «ринки чекають зниження» з одного джерела |
| Новий 8-K компанії зі списку | завжди від 45 | 8-K — це суттєва подія за визначенням SEC |
| Термінові категорії: хак біржі, рішення щодо ETF, регуляція крипти, великі санкції, удари по нафті/газу, OPEC+, рух BTC/ETH ≥7 %, сильний землетрус | ≥ 65 | категорія вже означає «важливо», тож потрібна лише помірна впевненість |
| Будь-що про мої компанії, BTC, ETH | ≥ 70 | ваші активи важливіші за загальний фон |
| Будь-що інше | ≥ 80 | лише справді великі події |

- Не більше **5 алертів на годину**; решта потрапляє в дайджест (з позначкою, скільки).
- **Тихі години 23:00–07:00**: алерти накопичуються й о ~07:00 приходять одним повідомленням 🌙.
- Новини старші за 12 год алертом не надсилаються; одна подія ніколи не надсилається двічі.
- CPI/PCE/payrolls за замовчуванням ідуть у дайджест; щоб отримувати їх алертом,
  розкоментуйте `macro_release: 55` в `alerts.always`.

Перевірити заголовок: `python -m market_monitor explain "..."` → останній рядок `alert:`.

### Дайджест (щодня о 20:00, `/digest_time`)

Ринок (BTC, ETH, Brent, газ, UST 10Y, VIX) → події на 7 днів → топ-5 подій із
кожної теми (🚨 позначає те, що вже було алертом) → блок «Мій список відстеження»
(лише якщо список не порожній) → стан джерел → «не є фінансовою порадою».
Надсилається першим запуском після вказаного часу, тому запізнення розкладу
GitHub Actions його не зриває.

### Команди бота

`/start`, `/list`, `/watch AAPL`, `/unwatch AAPL`, `/topics` (`/topics off crypto`),
`/threshold` (`/threshold 75`, `/threshold urgent 60`, `/threshold priority 65`),
`/digest_time 19:30`, `/status`.
Бот відповідає лише вашому `TELEGRAM_CHAT_ID`. Команди читаються на початку кожного
запуску (тобто з затримкою до інтервалу запуску), а зміни зберігаються в базі
поверх config.yaml.

## Список відстеження

```
/watch AAPL                      додати (назва й CIK підтягуються з бази SEC)
/watch SAP SAP SE                неамериканська компанія: тикер + назва для пошуку
/alias AAPL Apple, iPhone maker  інші назви (через кому)
/peers AAPL MSFT, GOOGL, Samsung конкуренти: тикери (великими) або назви
/suppliers AAPL TSM, Foxconn     постачальники
/sector XOM oil price*, refining ключові слова сектору
/peers AAPL -                    очистити
/list                            переглянути все
```

**Як новина прив'язується до компанії:**
- назва й псевдоніми — цілими словами, будь-який регістр (`Apple`, `APPLE`, але не `Pineapple`);
- тикер — з урахуванням регістру (`AAPL`). Короткі тикери або звичайні слова
  (`NOW`, `ON`, `A`, `KEY`) — лише у формах `$NOW`, `(NYSE: NOW)`, `NYSE:NOW`;
- новини про конкурентів, постачальників і сектор позначаються як «пов'язані»
  (🔗 у дайджесті, невеликий бонус до оцінки, але без окремого алерту).

Пряма згадка дає +25 до оцінки й поріг алерту 70 (замість 80); новий 8-K
надсилається завжди (від 45 балів).

**Блок компанії в дайджесті:** назва й галузь (з SEC), останні 8-K / 10-Q / 10-K
з посиланнями, нові документи SEC за період (📄), новини про компанію (📰) і
пов'язані події (🔗 конкурент / постачальник / сектор). Компанії, додані сьогодні,
теж отримують сьогоднішні новини: зіставлення повторюється під час збирання дайджесту.

## GitHub Actions (безкоштовний хостинг)

| Workflow | Коли | Що робить |
|---|---|---|
| `monitor.yml` | кожні 30 хв (:07 і :37) + вручну | команди бота → збір → скоринг → алерти → дайджест, якщо настав час |
| `digest.yml` | 18:02 і 19:02 UTC (= 20:02 за Братиславою влітку/взимку) + вручну | дайджест (надсилається один раз на день) |
| `tests.yml` | кожен push | pytest |

Обидва робочі workflow мають спільну `concurrency`-групу: два записи стану
одночасно неможливі. Поки секрети не задано, запуски завершуються з
попередженням «Not configured yet», а не з помилкою.

### Налаштування

1. **Settings → Secrets and variables → Actions → New repository secret**:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `STATE_ENCRYPTION_KEY`
   (обов'язкові), `FRED_API_KEY`, `SEC_CONTACT_EMAIL` (бажано).
   Ключ шифрування: довгий випадковий рядок, напр. `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
   **Збережіть його ще й у менеджері паролів**: без нього стан не відновити.
2. **Settings → Actions → General → Workflow permissions → Read and write**
   (щоб workflow міг оновлювати гілку `data`).
3. Розклад GitHub запускає workflow лише з **гілки за замовчуванням** (Settings → General → Default branch).
4. Перший запуск: **Actions → monitor → Run workflow** (галочка `dry_run` — лише друк у лог).

### Як зберігається стан між запусками

База SQLite після кожного запуску стискається, шифрується (Fernet, ключ із
`STATE_ENCRYPTION_KEY` через scrypt) і записується в гілку **`data`** одним
комітом (force-push). У тому ж коміті лежить попередня версія
(`state.prev.db.enc`) для відкату на один крок.

| Варіант | Чому ні / так |
|---|---|
| **гілка `data`** (обрано) | безкоштовно, без строку зберігання, видно в репозиторії; репозиторій не росте, бо коміт завжди один |
| `actions/cache` | кеш видаляється після 7 днів без використання, його не можна перезаписати під тим самим ключем |
| артефакти | зберігаються максимум 90 днів, завантажувати незручно |
| зовнішня БД / Gist | потрібні інші сервіси й токени |

Компроміси гілки `data`: репозиторій публічний, тож файл бачать усі, але без
ключа це лише шифротекст (список відстеження, 👍/👎 і т.п. не прочитати).
Якщо ключ хибний або файл пошкоджено, запуск падає **до** збереження: стан не
перезаписується порожньою базою. Push робиться з `--force-with-lease`: якщо інший
запуск встиг оновити гілку, цей запуск свої зміни не нав'язує.

Відкат на попередню версію: завантажте `state.prev.db.enc` з гілки `data` і
закомітьте його як `state.db.enc`.
