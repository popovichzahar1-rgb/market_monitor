# Market Monitor

Особистий конвеєр моніторингу подій, що впливають на ринки акцій і крипти.
Збирає новини й дані з відкритих джерел, оцінює їхню важливість для ринку й для
ваших компаній і надсилає в Telegram **термінові алерти** та **щоденний дайджест**.

> **Лише збір і фільтрація інформації.** Жодної автоматичної торгівлі, жодних
> порад. Рішення про гроші ухвалюєте ви. Не є фінансовою порадою.

Працює безкоштовно на GitHub Actions, без платних API й без викликів LLM.

## Як це працює

```
команди бота ─► збір (RSS, SEC, FRED, USGS, …, паралельно)
             ─► нормалізація ─► дедуплікація (URL / текст / схожі заголовки)
             ─► прив'язка до компаній зі списку
             ─► оцінка 0–100 (правила + FinBERT) ─► алерти ─► дайджест (раз на день)
```

Кожні 30 хвилин GitHub Actions запускає один прогін (~30 с). Стан (база SQLite)
зберігається між запусками в зашифрованому вигляді в гілці `data`.

## Налаштування за 15 хвилин

### 1. Бот у Telegram

1. Відкрийте **@BotFather** → `/newbot` → придумайте ім'я й логін бота.
2. Збережіть токен вигляду `123456789:AA...`: це **`TELEGRAM_BOT_TOKEN`**. Нікому його не показуйте.
3. Напишіть своєму боту `/start` (він поки мовчить, це нормально).
4. Відкрийте в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть
   `"chat":{"id":123456789`. Це **`TELEGRAM_CHAT_ID`**. Бот слухатиметься лише цього чату.

### 2. Безкоштовні ключі

- **FRED** (макродані США): https://fred.stlouisfed.org → My Account → API Keys → **`FRED_API_KEY`**.
- **SEC EDGAR** ключа не потребує, але вимагає контактний email у User-Agent → **`SEC_CONTACT_EMAIL`**.
- **Ключ шифрування стану** → **`STATE_ENCRYPTION_KEY`**:
  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```
  Збережіть його ще й у менеджері паролів: без нього збережений стан не відновити.

### 3. GitHub

1. **Settings → Secrets and variables → Actions → New repository secret**: додайте
   п'ять секретів вище (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `STATE_ENCRYPTION_KEY`
   обов'язкові; `FRED_API_KEY`, `SEC_CONTACT_EMAIL` бажані).
2. **Settings → Actions → General → Workflow permissions → Read and write permissions**.
3. **Settings → General → Default branch**: розклад працює лише з гілки за замовчуванням.
4. **Actions → monitor → Run workflow**:
   - спершу з галочкою `dry_run`, щоб побачити в лозі, що надіслалося б;
   - потім без неї. Перший запуск обробить ваш `/start` і, якщо є важливі події, надішле алерти.

Далі все працює саме. Поки секрети не задано, запуски завершуються
попередженням «Not configured yet», а не помилкою.

## Команди бота

| Команда | Що робить |
|---|---|
| `/start`, `/help` | список команд |
| `/list` | список відстеження з усіма зв'язками |
| `/watch AAPL` | додати компанію (назва й CIK підтягуються з SEC) |
| `/watch SAP SAP SE` | компанія не з США: тикер + назва для пошуку |
| `/unwatch AAPL` | прибрати |
| `/alias AAPL Apple, iPhone maker` | інші назви компанії |
| `/peers AAPL MSFT, GOOGL, Samsung` | конкуренти (тикери великими або назви) |
| `/suppliers AAPL TSM, Foxconn` | постачальники |
| `/sector XOM oil price*, refining` | ключові слова сектору |
| `/peers AAPL -` | очистити список |
| `/topics` · `/topics off crypto` · `/topics on crypto` | вимкнути/увімкнути тему в алертах і дайджесті |
| `/threshold` · `/threshold 75` · `/threshold urgent 60` · `/threshold priority 65` | пороги алертів |
| `/digest_time` · `/digest_time 19:30` | час дайджесту (Europe/Bratislava) |
| `/status` | стан джерел, алертів, моделі |
| `/feedback` | підсумок ваших 👍/👎 і підказки, що підкрутити |

Команди читаються на початку кожного запуску, тому відповідь приходить
із затримкою до ~30 хв. Зміни зберігаються в базі поверх `config.yaml`.

## Алерти й дайджест

### Коли надсилається алерт

Перевірки йдуть по черзі; спрацьовує перша, що підходить:

| Що | Поріг | Чому так |
|---|---|---|
| Тема вимкнена через `/topics` | ніколи | ваш вибір |
| Рішення центробанку (ФРС, ЄЦБ, BoE, BoJ, НБК…) | завжди від 55 | ставки рухають усі ринки; 55 відсікає здогадки з одного джерела |
| Новий 8-K компанії зі списку | завжди від 45 | 8-K — суттєва подія за визначенням SEC |
| Термінові категорії: хак/зупинка виведення на біржі, рішення щодо крипто-ETF, регуляція крипти (позови, заборони, закони), великі санкції, удари по нафті/газу/судноплавству, OPEC+, сильний землетрус | ≥ 65 | категорія вже означає «важливо» |
| Будь-що про мої компанії, BTC, ETH | ≥ 70 | ваші активи важливіші за загальний фон |
| Будь-що інше | ≥ 80 | лише справді великі події |

- Не більше **5 алертів на годину**; решта потрапляє в дайджест (там видно, скільки їх).
- **Тихі години 23:00–07:00**: алерти накопичуються й о ~07:00 приходять одним повідомленням 🌙.
- Новини старші за 12 год алертом не надсилаються; одна подія ніколи не надсилається двічі.
- CPI/PCE/payrolls за замовчуванням ідуть у дайджест. Щоб отримувати їх алертом,
  розкоментуйте `macro_release: 55` в `alerts.always` у config.yaml.

Усе це в розділі `alerts:` у `config.yaml`.

### Дайджест (щодня о 20:00)

1. 📈 Ринок: Brent, газ, UST 10Y, VIX (і BTC/ETH, якщо увімкнено джерело цін).
2. 📅 Події на 7 днів: релізи CPI, payrolls, ВВП, FOMC.
3. Топ-5 подій із кожної теми (🚨 позначає те, що вже було алертом).
4. 💼 Мій список відстеження (лише якщо список не порожній): останні 8-K/10-Q/10-K,
   нові документи SEC, новини про компанію, пов'язані події (конкурент / постачальник / сектор).
5. 🛰 Стан джерел і рядок «не є фінансовою порадою».

Дайджест надсилає перший запуск після вказаного часу, тому запізнення
розкладу GitHub не зриває його.

## Список відстеження

Пряма згадка компанії в новині визначається так:

- **назва й псевдоніми** шукаються цілими словами в будь-якому регістрі (`Apple`, `APPLE`, але не `Pineapple`);
- **тикер** шукається з урахуванням регістру (`AAPL`);
- **короткі тикери або звичайні слова** (`NOW`, `ON`, `A`, `KEY`) ловляться лише у формах
  `$NOW`, `(NYSE: NOW)`, `NYSE:NOW`.

Пряма згадка додає +25 до оцінки й знижує поріг алерту до 70. Новини про
конкурентів, постачальників і сектор позначаються як пов'язані (🔗, +8 до оцінки, без окремого алерту).

У `config.example.yaml` є три **приклади** формату (AAPL, ASML, XOM).
Це не рекомендації. Ваш робочий `config.yaml` починається з порожнього списку.

## Оцінка важливості й налаштування правил

`оцінка (0–100) = правила + величина даних + бонуси + тон тексту`

- **Правила** (`scoring.rules`): ключові слова з вагами. Друге правило, що
  спрацювало, додає половину своєї ваги, третє — чверть. Шумові правила (opinion,
  podcast, «best stocks to buy») мають від'ємну вагу.
  - Ключове слово малими літерами збігається з будь-яким регістром.
  - Слово з великою літерою (`Fed`, `SEC`, `ETF`, `US`) враховує регістр.
  - `*` означає будь-яке закінчення: `sanction*` знайде «sanctions», «sanctioned».
  - `also_any` — друга умова, що теж має виконатися.
- **Дані**: величина руху ціни, великі релізи (CPI, PCE, payrolls), магнітуда й PAGER землетрусу, пункти 8-K.
- **Бонуси**:
  - вага джерела (офіційні ФРС/ЄЦБ +25, GDELT −5);
  - +6 за кожне додаткове джерело, що пише про ту саму подію;
  - BTC/ETH +10;
  - ваші регіони +5;
  - компанія зі списку +25, пов'язані новини +8.
- **Тон** (FinBERT, локально): до +10 за виразний тон і ще +5 за явно негативний.
  Модель запускається лише для записів, що вже набрали ≥ 25 балів, тому це займає секунди.
  Без моделі працює вбудований фінансовий словник.

Перевірити, як оцінюється заголовок і чи буде алерт:

```bash
python -m market_monitor explain "OPEC+ agrees surprise output cut" --source rss:oilprice
```

## Зворотний зв'язок 👍/👎

Під кожним алертом є кнопки **👍 Корисно** / **👎 Шум**. Під нічною добіркою вони
пронумеровані для кожного алерту. Голос можна змінити, натиснувши іншу кнопку.

`/feedback` (або `python -m market_monitor feedback --days 30`) показує:
- скільки 👍 і 👎 отримало кожне правило, категорія і джерело;
- найвищі за оцінкою алерти, позначені як шум;
- **підказки**, наприклад «Правило «crypto_regulation»: 4 з 4 — шум. Зменште `weight`…»,
  «Джерело rss:decrypt: … зменште scoring.source_weights…», «Спробуйте /threshold urgent 70».

Автоматично нічого не змінюється: ви бачите, чому, і правите `config.yaml`
або пороги командами. Алерти з оцінками зберігаються довше за 30 днів: це історія налаштування.

## Джерела

| Модуль | Що дає | Ключ | Стан за замовчуванням |
|---|---|---|---|
| `rss` | ФРС, ЄЦБ, Банк Англії, Банк Японії, прес-релізи SEC, CNBC, MarketWatch, BBC, Al Jazeera, OilPrice, EIA, Kyiv Independent, SCMP, CoinDesk, Cointelegraph, Decrypt | — | ✅ (≈220 записів за 48 год, ~3 с) |
| `sec_edgar` | 8-K/10-Q/10-K/6-K/20-F компаній зі списку, профіль і останні звіти | `SEC_CONTACT_EMAIL` | ✅ |
| `fred` | CPI, core CPI/PCE, payrolls, безробіття, HICP єврозони; різкі рухи DFF, 10Y, VIX, Brent, газу; календар релізів | `FRED_API_KEY` | ✅ |
| `usgs` | землетруси M ≥ 6.5 або PAGER orange/red | — | ✅ |
| `gdelt` | світовий пошук новин за темами | — | ⛔ з IP-адрес GitHub майже завжди HTTP 429; локально працює |
| `coingecko` | різкі рухи BTC/ETH і всього крипторинку, ціни для дайджесту | — | ⛔ `robots.txt` API забороняє ці шляхи (див. нижче) |

Правила роботи з джерелами:
- лише офіційні API, RSS і відкриті дані;
- `robots.txt` перевіряється, заборонене не завантажується;
- для кожного хоста є пауза між запитами (SEC ≤ 10 запитів/с, GDELT 1 запит/5 с);
- незмінені стрічки віддають `304`;
- кожне джерело має бюджет часу 90 с, і збій одного джерела не зупиняє решту.

**CoinGecko.** API офіційний і безкоштовний, але `robots.txt` на `api.coingecko.com`
забороняє ці шляхи, тому джерело вимкнено. Варіанти: (а) дозволити саме його
(`sources.coingecko.enabled: true` + виключення з перевірки robots), (б) інше
офіційне API цін, (в) лише щоденні ціни з FRED.

## GitHub Actions і збереження стану

| Workflow | Коли | Що робить |
|---|---|---|
| `monitor.yml` | кожні 30 хв (:07 і :37) + вручну (`dry_run`) | команди → збір → оцінка → алерти → дайджест, якщо час |
| `digest.yml` | 18:02 і 19:02 UTC (= 20:02 за Братиславою влітку/взимку) + вручну (`force`) | дайджест (раз на день) |
| `tests.yml` | кожен push | pytest |

Обидва робочі workflow мають спільну `concurrency`-групу: два записи стану одночасно неможливі.

### Заміри (14.10.2026, живі джерела)

| Крок | Перший запуск | Звичайний запуск |
|---|---|---|
| підготовка: Python, залежності, FinBERT із кешу | 61 с (з експортом моделі) | 19 с |
| збір | 224 с (через GDELT, тепер вимкнений) | 2,9 с |
| оцінка (FinBERT ONNX, ~60 записів) | 1,8 с | 4,0 с |
| збереження стану | ~3 с | ~3 с |
| **разом** | ~5 хв | **≈ 30 с** |

**Інтервал.** Для публічного репозиторію хвилини безкоштовні: 30 хв — це ≈ 25 хв
роботи на день, можна й 15 хв (`cron: "7,22,37,52 * * * *"`). Для приватного
(2000 хв/міс, кожен запуск рахується мінімум як 1 хв) 30 хв дають ≈ 1500 хв/міс,
тож це мінімум; 60 хв — із запасом. Розклад GitHub зазвичай запізнюється на 2–15 хв.

### Як зберігається стан

Після кожного запуску база SQLite перевіряється (`integrity_check`), стискається,
шифрується (Fernet; ключ виводиться з `STATE_ENCRYPTION_KEY` через scrypt) і
записується в гілку **`data`** одним комітом. Там же лежить попередня версія
(`state.prev.db.enc`) для відкату на крок назад.

| Варіант | Чому ні / так |
|---|---|
| **гілка `data`** (обрано) | безкоштовно, без строку зберігання; репозиторій не росте (коміт завжди один) |
| `actions/cache` | видаляється після 7 днів без використання, не перезаписується під тим самим ключем |
| артефакти | максимум 90 днів, незручно завантажувати назад |
| зовнішня БД / Gist | інші сервіси й токени |

Безпека:
- Для публічного репозиторію файл бачать усі, але без ключа це лише шифротекст.
- Хибний ключ або пошкоджений файл зупиняють запуск **до** збереження, тож стан не перезаписується порожньою базою.
- Push іде з `--force-with-lease`, тому паралельний запуск нічого не затре.

**Відкат:** завантажте `state.prev.db.enc` з гілки `data` і закомітьте його туди як `state.db.enc`.
**Почати з нуля:** видаліть гілку `data`.

## Локальний запуск і розробка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[ml,dev]"
cp .env.example .env                        # впишіть секрети
python -m pytest                            # офлайн-тести на фікстурах (~4 с)
python -m market_monitor run --dry-run      # живі джерела, друк замість відправки; команди бота не «з'їдаються»
python -m market_monitor run                # справжня відправка
python -m market_monitor digest --force     # дайджест зараз
python -m market_monitor status             # стан джерел
python -m market_monitor feedback           # звіт 👍/👎
python -m market_monitor explain "..."      # чому така оцінка
```

FinBERT локально (необов'язково, ≈2 ГБ на `torch`, лише один раз):

```bash
pip install -e ".[export]"
python scripts/export_finbert.py --out models/finbert-onnx
```

Конвенції коду, структура модулів і правила для тестів описані в [CLAUDE.md](CLAUDE.md).

## Якщо щось не так

| Симптом | Що перевірити |
|---|---|
| Бот мовчить | `/status` (відповідь прийде з наступним запуском); Actions → monitor: чи є попередження «Not configured yet»; чи правильний `TELEGRAM_CHAT_ID` |
| «cannot decrypt state» | `STATE_ENCRYPTION_KEY` змінився. Поверніть старий ключ або видаліть гілку `data` (стан почнеться заново) |
| Помилка push у кроці persist | Workflow permissions → Read and write |
| Джерело ❗ у дайджесті | `/status` показує помилку; 404 — стрічка змінила адресу (виправте URL у `config.yaml`); `robots.txt disallows` — сайт забороняє, вимкніть стрічку |
| Забагато алертів | `/feedback`, потім `/threshold 85` або `/threshold urgent 70`; `/topics off …` |
| Замало алертів | `explain` для пропущеного заголовка; знизьте пороги або додайте ключові слова в `scoring.rules` |
| Немає SEC-документів | `SEC_CONTACT_EMAIL`; компанія не з США (SEC її не знає) |
| Запуск довгий | job summary в Actions показує час кожного джерела |
